# Prompt

See the Stack section of the [platform](/design/platform.md) design:
SvelteKit with `adapter-static`, one TypeScript interface to the core, and
types generated by `npm run generate`. Keep the `rd:` performance measures so
the benchmarks compare old and new. Introduce the renderer interface (B3) here.

# Plan

The old dashboard (`src/rdstudio/web/`) stays the one served until the new one
(`app/`) matches it, page by page, checked with screenshots against it.

1. **Scaffold and knowledge pages.** Done (see Progress).
2. **The other pages:** Learn, Changes, Review, Reports, Skills and agents,
   procedures. Done.
3. **Graph and map,** the imperative d3 code wrapped in components, with the
   renderer interface (B3) introduced here; the layout worker and the `rd:`
   measures kept, so the benchmarks compare.
4. **Switch over:** `rdstudio build` uses the app's build; the old dashboard is
   deleted; the static files (themes, fonts, service worker) move into
   `app/static/`; the release bundles the built app.

# Progress

- Slice 1 (2026-09-30): `app/`, a SvelteKit 2 app with Svelte 5 runes, built
  by adapter-static as a single-page app with hash routing, so every existing
  address (`#/k/...`, `#/d/...`, `#/path/...`) works unchanged and the files
  can be served from any folder. The data files' shapes are typed once, in
  the core (`site.ts`), and used by both the build and the app. The learner
  record goes through a client generated by HeyAPI from rdstudio serve's
  OpenAPI description (`npm run generate`, `mise run generate`). Ported: the
  shell (tabs, counts, live updates, the drawer, full screen), the knowledge
  tree, note and folder pages with the details panel, Markdown with maths,
  code, footnotes, task lists and Mermaid, and Settings. Other tabs say they
  are not ported yet.
- Rendered Markdown is now sanitised (DOMPurify): notes may contain HTML and
  come from agents and other people, and the dashboard holds the learner
  record's write token.
- Checked against the old dashboard, pixel for pixel on the differential
  geometry bundle: the note and folder pages and Settings are identical. The
  tree differs on purpose: the old one opened every folder on the home page
  (an empty string counted as "open") and never opened the folders leading to
  the current note (a "k:" prefix in the comparison); the new one opens the
  path to the current page and remembers what the reader opens.
- Loading a note with maths, over the slow-link profile: 1.8 s and 402 KB in
  30 requests, against 2.4 s and 519 KB in 40 for the old dashboard; on the
  desktop about 0.2 s, 40 ms slower than the old.
- TypeScript 6 across the workspace: svelte-check and HeyAPI need the
  TypeScript API, which the Go-based TypeScript 7 does not offer yet.
- `npm audit` reports advisories in `cookie` (SvelteKit's server rendering,
  not used) and `js-yaml` (HeyAPI's generator, reading our own file); neither
  reaches the built dashboard, and the offered fixes are downgrades.
- Slice 2: Learn, Changes, Review, Reports and the report viewer, Skills and
  agents with their pages, and Procedures with the flow graph and inspector
  (its layout now a pure function, `lib/flow.ts`, drawn declaratively).
  Compared pixel for pixel with the old dashboard on the differential
  geometry bundle and on this repository's (for its procedures), at desktop
  and phone widths, with steps and transitions selected: identical, apart
  from two bugs in the old dashboard, fixed here. The Learn page printed
  "[object HTMLParagraphElement],[object HTMLPreElement]" instead of how to
  turn the learner record on; and the tree differences above. The Review
  page is a pixel shorter at the very end.
- Found on the way: `<svelte:body class:...>` is not applied (the drawer did
  not open; svelte-check does not flag it), and a selection held in `$state`
  is proxied, so comparing it with the graph's own objects failed; both fixed.
