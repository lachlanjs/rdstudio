M14: Axis finds things

All six tasks of the milestone are built, on the branch feat/axis-finds. A question can be asked on the Atlas and is answered beside the map, with the notes it came from marked. Axis has two more tools over the code index. Notes can be searched by meaning with a small model that runs on the device. Nothing is merged or pushed.

What changed

  • T85, Ask Atlas. A box on the Atlas, an answer card, and marks on the map: notes found, links followed, a passage beside each note the answer rests on. Each sentence the model quotes is checked against its note. packages/cli/src/atlasask.ts, app/src/lib/views/ask.js, gridmap.js.
  • T86, code index tools. search_symbols and outline_code in lookup.ts.
  • T87, the trial. The embedding model through WebAssembly, timed and sized.
  • T88, the measure. 45 questions with known answers in bench/retrieval/.
  • T89, search by meaning. packages/cli/src/embed.ts, the tool find_similar for Axis and on the MCP server, a cache in .rdstudio/, and code search that works without git.
  • T90. A third mark on the Atlas for notes found by meaning.
  • Two new dependencies of the command line: onnxruntime-web and @huggingface/tokenizers.
  • Notes: the designs "Ask Atlas" and "Search by meaning", and each task's Done or Result section.

Results

The measure

The share of 45 questions for which a note that answers is among the first k notes returned, on this knowledge base, with the built code.

From mise run bench:retrieval. "Either" asks both and takes the better place.

  • The questions were written by the agent, who knew the notes, in words the notes avoid. That favours search by meaning.
  • Each search is one query. In the one real trial on a question keyword search missed, the model reworded its keyword searches, found the answer, and never called search by meaning. So these figures understate keyword search in an agent's hands.
  • 45 questions: one question is two points.

Deviations and issues

  • T89 was conditional on the measure. The agent judged the measure to support it and went ahead; the decision is yours to reverse.
  • The model is not in git (34 MB). A checkout fetches it with mise run embed:model; the npm package carries it. Without it, search by meaning is simply not offered.
  • The Python wheel carries no model.
  • WebKit was not tested: only Chromium is installed here. The desktop and phone apps would use WebKit on Apple devices and Linux.
  • The code index reads Python and C++ only, so the two code tools do nothing useful in this repository, which is TypeScript.
  • Ask Atlas marks nothing in the code view, and maths in the answer card is not typeset.
  • The measure scores by note, not by section as planned.
  • The walkthroughs for learning, the teacher, composing and reshaping (T73) and sign-in were not run; they were already failing or flaky before this work.
