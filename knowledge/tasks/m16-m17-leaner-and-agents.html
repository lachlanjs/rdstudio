Ten of the eleven tasks recorded on 2026-10-08 are built, on the branch feat/m16-leaner; the eleventh was dropped by the developer. The Python implementation is gone. Axis can propose notes, changes and moves from the Atlas, and writes nothing until one is accepted. Nothing here was tried against a real model, a real Claude Code or opencode session, or a real gateway: every check used a stand-in.

The Python tests fell because what they tested was removed; the four left test the launcher and the benchmark's generator. The two new browser suites are e2e/propose.py (20 checks) and e2e/agents.py (24 checks, against a real rdstudio mcp process).

Deviations and issues

  • Two claims made when the tasks were written were wrong. There were not three separate agent set-ups: the loop was already shared (T100). And the page already learnt of an outside edit by itself, by asking for the build's version on a timer (T107).
  • The limits are on the Teacher page, beside the tier models, not on Settings as first said. And an output limit set is what is sent, so it can raise rdstudio's own figure as well as lower it: a model that reasons needs the higher one.
  • Found by running, not by tests. A proposed change whose new text holds the old could be made twice. At a terminal, provider init took "n" as a path, named a bare address "0", and printed a stack trace on Ctrl+D. All four are fixed, the first with a test.
  • The sign-in browser suite failed once and passed when run again, on a slow machine. It was not looked into further.
  • The benchmark's load and build timings no longer compare with the baselines kept, which timed the Python build.

Not checked

  • The five browser suites that need the differential geometry test bed: edit, compose, reshape, learn, teacher. They cover routes that moved when serve.ts was split.
  • Anything with a real model: whether it proposes sensibly, or stops at a limit as expected.
  • A real Claude Code or opencode session. The hook's field names for Claude Code's file tools were not confirmed from its documentation.
  • A real corporate gateway, private authority or proxy with provider init.
