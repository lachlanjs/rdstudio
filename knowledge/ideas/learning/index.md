# Idea

* [Alpha trials](alpha-trials.md) - Four trials the developer will run once an alpha of the understanding layer exists, each chosen to test a different part of the model.
* [Autoethnography of learning with the tool](autoethnography.md) - The developer studies their own learning with the tool as a more rigorous test of it, using single-case designs and measures the tool did not set, with its bias acknowledged.
* [Editing from the dashboard](dashboard-editing.md) - What it takes to let the dashboard write, which the manifesto's malleable map needs; moderate work and no new dependencies.
* [Features sorted by the PID model](pid-feature-map.md) - Proposed understanding features grouped by the part of the control loop they serve, with corrections and extensions to the control theory in the motivation note.
* [Nested networks and links shown at their scale](nested-links.md) - Classify each link by the lowest folder containing both ends, and draw it only at that scale, so cross-scale links can be examined separately.
* [Private learner record, landmarks and team use](learner-record.md) - Keep what a person knows separate from what is true about the project, private by default, tied to note versions, with AI-assisted choice of landmarks.
* [Professional mode for understanding features](professional-mode.md) - How to present motivational and learning features so they suit a work context, modelled on training-load dashboards and test coverage rather than games.
* [Tours, exercises and catch-up views](tours-and-exercises.md) - Concrete dashboard features for journeying, pathfinding, reciting landmarks and filling gaps, plus views for catching up on change.
* [Where the understanding layer lives](tool-boundary.md) - Recommendation to build the understanding features in rdstudio on a branch as a separable, switchable layer, rather than as a new tool; name candidate par.
